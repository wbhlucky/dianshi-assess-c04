# 响应偏离表自动生成器（bidtable）

读一个招标资料包（`00_投标范围.txt` + `01_招标文件_*.pdf` + `02_厂商资料/` + `03_响应偏离表_模板.xlsx`），
产出一张严格 10 列的《响应偏离表》xlsx，外加一份旁挂的人工复核 Markdown 报告。

设计依据、数据事实基线与全部取舍记录都在 `agent.md`（1292 行）。本文件是交付说明，
按 `agent.md` §11 的清单写成 5 节：安装与运行 / 处理流程 / AI 工具使用记录 / 自测成绩 / 已知问题。

**一句话结果**：5 个训练包共 205 条，覆盖率 `1.000`，偏离类型准确率 `0.927`（朴素基线 0.707），
证明材料命中率 `0.941`，位置命中率 `0.931`，多余条目最差包 `1`，关键项风险识别 `4/5`。
最后那 1 条缺口是离线环境的物理天花板，成因与证据见 §5.1。

## 1. 安装与运行

### 1.1 环境

Python **3.12+**。主流程 3.10 也能跑，但 `tools/coverage_report.py` 用 PEP 669 的
`sys.monitoring`，需要 3.12。

```powershell
pip install -r requirements.txt
```

`requirements.txt` 只列**当前环境已验证可用**的包（`agent.md` §10.2 第 6 条）。
`pandas` / `numpy` / `rich` 环境里有，但一个都没引：本项目全部是逐行文本与坐标运算，
引 DataFrame 只会把「这一行为什么判成这样」藏进一层抽象里。

### 1.2 环境变量

| 变量 | 作用 | 缺省 |
|---|---|---|
| `LLM_API_KEY` | 模型 Key，**优先级最高** | 无 |
| `DASHSCOPE_API_KEY` | 兜底 Key，`LLM_API_KEY` 缺失时才读 | 无 |
| `LLM_BASE_URL` | OpenAI 兼容端点 | 按 Key 来源推断（见下） |
| `MODEL_TEXT` | L2 语义匹配用的文本模型 | `deepseek-v4-flash` |
| `MODEL_STRONG` | L3 难判定裁决用的强模型 | `deepseek-v4-pro` |
| `MODEL_VISION` | L1 结构化 OCR（视觉模型） | `qwen3.7-plus` |
| `MODEL_OCR` | L1 纯文本 OCR | `qwen-vl-ocr` |
| `BIDTABLE_CACHE` | 阶段缓存与 LLM 缓存的根目录 | `.cache` |

三条规则值得单独说，因为它们容易踩：

1. **Key 优先级是 `LLM_API_KEY` > `DASHSCOPE_API_KEY`**，命中第一个就停。
   Base URL 优先级是 CLI `--base-url` > `LLM_BASE_URL` > 按 Key 来源推断
   （`LLM_API_KEY` 推 `parvis.zjugpt.com`，`DASHSCOPE_API_KEY` 推 `dashscope`）。
2. **`MODEL_*` 环境变量压过 CLI**。`load_config` 里是 `_env("MODEL_TEXT", model_text or 默认值)`，
   这是有意的：CI 上换模型不该改命令行。
3. **没有 Key 时 `offline` 被强制置真**（`offline = offline or api_key is None`）。
   所以「什么都不配」等价于 `--offline`，不会去发一个注定失败的请求。

本仓库**不写任何 Key**。`bidtable/config.py` 只实现「从哪儿读」，不保存值。
`tests/invariants/test_no_leakage.py` 会全仓扫 `sk-` 前缀、`*_API_KEY=<值>` 赋值、
`Bearer <token>` 三种泄漏形态，命中即红。

### 1.3 一条命令

```powershell
python run.py --pack 训练集/P1 --out out/P1.xlsx --report out/P1.review.md
```

stdout 只有**一行**收尾摘要，进度与告警全走 stderr：

```
P1：17 行｜无偏离=10 正偏离=1 负偏离=3 未响应=3｜关键项风险 1 行｜待复核 15 行｜告警 2 条
```

这样 `python run.py ... | tee log` 或 `> summary.txt` 拿到的就是干净的一行，
不会被 7 个阶段的进度刷屏。`--out` 的父目录不存在会自动创建。

退出码分三层，`agent.md` §4.5 定的契约：

| 码 | 含义 | 例子 |
|---|---|---|
| `0` | 成功 | — |
| `1` | 输入层面的问题，改了输入就能重跑 | 包目录不存在、缺 `01_招标文件_*.pdf`、`--section-policy` 取值不对 |
| `2` | 无法产出结果 | 招标 PDF 损坏/加密/0 页、xlsx 被 Excel 占用、LLM 鉴权失败 |
| `130` | Ctrl-C | — |

**任何非零退出都不裸露 traceback**，只打「一行可行动的中文消息」。
`run.py` 只捕获 `errors.BidTableError` 与 `KeyboardInterrupt`；真正的 bug 仍然会抛栈，
这是刻意的——把 `ValueError` 也吞掉等于把 bug 伪装成「输入有问题」。

### 1.4 质量门禁怎么跑

`agent.md` §6.9 定了 5 道门禁。这台机器上 `ruff` / `coverage` / `pytest-cov` 都装不上，
所以有两道换了等价实现，**门禁本身没有取消**：

```powershell
# 1. 离线套件全绿且 <60s（实测 438 项 / 40.0s）
python -m pytest tests -q

# 2. 真跑 pipeline + grade.py 的评估层（默认被 addopts 反选，要显式 -m eval）
python -m pytest tests/eval -q -m eval

# 3. 行覆盖率 >=70%（bidtable/ 排除 llm/）—— 实测 96.2%
python tools/coverage_report.py --json out/coverage.json --missed

# 4. ruff check 0 error 的替身
python -m compileall -q bidtable run.py tools tests grade.py

# 5. 5 包自测成绩表
python -m bidtable.selfcheck --packs 训练集 --json out/selfscore.json --no-cache
```

`tools/coverage_report.py`（232 行）是自己写的覆盖率工具，理由写在它的 docstring 里，
这里只提两条使用约束：它**在当前进程里驱动 `pytest.main()`**（`sys.monitoring`
监控不了子进程），所以 `tests/eval/` 起的子进程不在测量范围内——离线套件本来也不跑 eval，
口径自洽；它的「可执行行」分母用 AST 数，与 `coverage.py` 接近但不逐行相同，
**百分比请读作本工具口径下的门禁值，不要拿去跟 `coverage report` 对账**。

`pytest.ini` 里有一条 `--import-mode=importlib` 不能删：`tests/unit/test_errors.py` 与
`tests/integration/test_errors.py` 同名（一个盯错误分层，一个盯跨进程契约），
默认的 prepend 模式会在收集阶段直接报 `import file mismatch`。

### 1.6 selfcheck 用法


### 1.7 非 UTF-8 控制台

Windows 子进程的 stdout/stderr 编码跟**平台 ANSI 码本**走（这台机器是 gbk/cp936），不是 UTF-8。
今天退出码仍然是 0，只因为输出的每个汉字都在 GBK 里；一旦加进一个码本外的字符
（比如某个生僻设备名或 emoji），成功的运行会变成 `UnicodeEncodeError`。逃生口：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
```

`tests/eval/test_cli_contract.py` 有一条用例专门把子进程钉在 `cp936` 上跑，
验证摘要行在窄码本控制台里逐字节不变。

## 2. 处理流程

### 2.0 流水线

`bidtable/pipeline.py` 的 7 个阶段，前 4 个可缓存（`CACHED_STAGES`）：

```
00_投标范围.txt ─┐
                 ├─> [1 scope ] 标的/设备名/数量/is_service        ─┐
02_厂商资料/ ────┼─> [2 vendor] docx 表格 + 样本 PDF + 报告 OCR     │
                 │            + lotmap（型号 <-> 标的 绑定）        │
01_招标文件.pdf ─┴─> [3 tender] 章节定位 + 版面族 A/B/C + 跨页拼接  │
                                                              ↓   ↓
                     [4 cut   ] 折叠（N）+ 范围裁剪 + 分节 S4 ──> Requirement[]
                                                              ↓
                     [5 match ] 确定性优先级 -> LLM 兜底      ──> Match[]
                                                              ↓
                     [6 judge ] 单位换算 -> 方向 -> 比较符 -> τ ──> Row[]
                                                              ↓
                     [7 write ] 严格 10 列 xlsx（+ 旁挂复核 md）
```

`--from-stage` 就是从这条链的某一环重算，之前的阶段读 `.cache/stages/` 里的冻结 JSON。
缓存键是 `pack_hash`（16 位十六进制，**不读文件内容**，只看路径与清单），
所以改了 PDF 内容而没改文件名时缓存不会失效——这是已知的取舍，见 §5.6。

### 2.1 章节定位与三种版面族

定位分两步：先判版面族，再按族找参数页。判定顺序是 **C -> A -> B**，
因为 C 的块标题最独特、A 的列头文字次之、B 只能兜底：

| 族 | 训练包 | 识别特征 | 参数形态 |
|---|---|---|---|
| **A** | P1/P2/P3 | 页面上出现列头 `技术规格及主要参数` | `二、采购清单` 6 列表，参数全挤在一个**跨页大单元格**里 |
| **B** | P4 | `五、技术要求` 独立成行 | `序号｜技术要求` 双列表 |
| **C** | P5 | ≥2 个不同的 `N-科室-设备名技术参数` 块标题 | 每块内部是行内编号项 |
| **?** | — | 以上都不命中 | 降级为「全文捞参数行」，全部行按最低档置信度输出 |

**目录页陷阱**是这里最阴的一个坑。P1/P2/P3 的 p2 是目录，里面的 `第二章项目需求`
与正文章节标题**逐字相同**。所以 `find_pages(doc, needle, after=2)` 一律要求页码 > 2
（常量 `TOC_MAX_PAGE = 2`）。少了这道闸门，P1 会定位到 `[2, 8]` 而不是 `[8]`，
整张表从目录页开始抽，全错。

A 族还要额外要求「同页出现列头 `技术规格及主要参数`」才算正文；参数区向后扫描的
页数上限是 `MAX_PARAM_PAGES = 40`，那只是防走飞的保险丝，不是业务常量
（训练集里 A 族最长 7 页，P3 的 p8–p14）。

C 族的块标题正则需要**故意放宽**：P5 里实测三种写法
（`1-EICU-床旁血液净化系统技术参数`、`2-病理科-切片机参数`、`6-骨科-高清关节镜`），
连字符有半角也有全角。所以 `C_BLOCK_RE` 只要求 `N-x-y` 的形状，
再用 `_looks_like_block()` 做真伪闸门（名字以「参数」结尾，或科室以
`科/中心/室/ICU/部/病区` 结尾），挡掉 `1.19 可选配弹性定量分析技术…` 这类散文。

### 2.2 抽表：为什么不用 `find_tables()`

PyMuPDF 自带 `page.find_tables()`，一开始就用了，然后在 P1 p8 上只吐出 **3 行**，
而那一页实际有 15 条参数。原因是 A 族的参数单元格是**跨页的巨型单元格**：
表格检测算法按闭合框线切表，跨页单元格的框线在页边界处不闭合，
于是整页被判定为「不是表」或者只认出了表头那几行。

改成自己抽：`cellstitch.py` 只取两样东西——**横线与竖线的坐标**
（`page_rules(page) -> (HRule[], VRule[])`，`HRule(y, x0, x1)` / `VRule(x, y0, y1)`），
然后 `column_edges()` 用竖线的 x 聚成列边界、`row_bands()` 用横线的 y 聚成行带，
最后 `cell_text(page, x0, x1, y0, y1)` 用 `page.get_text("words")` 把落在该矩形里的词
按 y 再按 x 排序拼回来。

这样做的好处是**完全绕开「表是否闭合」这个判断**：只要页面上有横竖线，就能切出格子。
P1 p8 实测 7 条列边界 `[62, 94, 159, 372, 408, 443, 540]`、4 个行带，15 条参数一条不少。
代价是 `cell_text` 有两个已知瑕疵：字形横跨 x 裁剪线时会被截断，
y 裁剪线切在字形腰部时会插入一个空格（§5.6）。

### 2.3 跨页单元格拼接

A 族的参数大单元格从 p8 一直流到 p10（P3 是 p8–p14）。拼接按 **x 区间**做，不按行号：

1. 每页独立算出列边界 `cols` 与行带 `band_ys`；
2. `_page_bands(page, page_no)` 返回 `(cols, bands)`，当 `len(cols) < MIN_COLS + 1`
   （`MIN_COLS = 4`）时返回 `(cols, [])`——这就是「这一页不是参数表」的信号，
   P1 的扫描正是在 p10 之后靠它停住的；
3. 续页的前两列（序号列、设备名列）天然是空的，因为内容只往第 3 列的大单元格里流。
   这个「**续页带**」形态（`c0 == '' and c1 == ''`）就是判定「本带是上一页的延续」的
   依据，于是它的文本被 append 到上一页那个单元格的行序列末尾，而不是新起一行；
4. `CUT_MARKERS` 在**行级别**切断，不在页级别。标记是
   `本采购清单中所列技术规格及主要参数为最低要求` / `本项目核心产品为` / `三、商务要求`。
   所以 P1 的 p10 仍然留在 `param_pages` 里（那一页前半是参数、后半才是套话），
   这也解释了为什么 `agent.md` 原文写的「参数页 8–9」实测是 `(8, 9, 10)`。

### 2.4 编号、标记与标题判别

`numbering.py`（503 行）负责把一行文本判成 `heading / item / continuation`，
并归一编号。要处理的真实形态（`agent.md` §7.1 的 EC-H 等价类）：
`1.` `1、` `1.1、` `1.1`（裸空格）`1.9.1`（三级）`▲2.`（标记在前）`1.7★`（标记在后）
`*21.1`（半角星）`（1）（2）（3）`（括号子项）`1．2`（全角点）。

`marks.py` 把 `★` / 半角 `*` 统一成 `★`，`▲` 原样保留，空标记就是空串——
`00_投标范围.txt` 的末行明确写了「部分文件用半角 `*` 表示同样含义，按 `★` 处理」。
标记从序号里剥出来放进第 5 列，但 **`招标要求（原文）` 列保持逐字原文**：
A 族的 `▲2.最大单脉冲能量5J。（大于5J 为优于）` 就连 `▲` 一起留着。
这是 P1 与 P4 的一个真实差异（P4 的原文列不含标记字符），
所以任何「原文列应该无标记」的断言都是错的。

标题与引导句**不输出成行**（`is_heading=True` 的行在 `cut` 阶段被丢掉，
但计入 `stage_counts` 的「标题/引导句（不输出）」）。P4 的
`主机系统要求`、`热蒸汽治疗系统专用软件要求` 就是这样被挡住的。

### 2.5 裁剪与分节

`scope.py` 按 `00_投标范围.txt` 裁掉不在投标范围内的段落：设备标的的**售后服务要求**
（`agent.md` §3.7 第 1 条）、商务要求、空白模板行、页尾套话。P5 在这一刀上裁掉 26 条
（标的 1/5/8/12 各 7/3/7/9 条），每裁一处都进 `skipped` 清单并写明理由，
最终体现在复核报告的第 4 节，不是静默丢弃。

`section.py` 的 `分节` 是四个策略里唯一会**改变对齐键**的一环，所以做成旋钮
（`s4/s2/s1/off`）而不是硬编码。默认 `s4` 是从 5 个包的标准答案**反推拟合**出来的规则集，
核心是「用中文序数标题（`一、`/`五、`）或引导句做一级、整数编号做二级，
两级之间用 `" / "` 连接」。填充率诊断（`diagnose`）会在填充率 > 80% 时告警——
P3 是 100%，但那**恰好是正确的**（P3 的参数区真的由多级标题组织），
所以告警文案里把这种情况写明了，而不是简单判成异常。

`fold.py` 处理 `（N）` 子项，这是 H3 阶段最大的一个得分点，规则完全由**厂商证据**驱动：
只有 `（N）` 展开出来的子项才是候选；只有服务标的参与（且至少声明了一个服务标的）；
厂商证据的项目名命中**父项标题**而不命中任何子项标题 -> 折叠成一行，否则保持展开。
P1 的 `*_服务方案.docx` 写的是父项「设备运行维护」-> 折叠 -> 标的2 序号 `{1, 2}`；
P2 写的是子项「日常巡检维护」-> 展开 -> `{1, 2.1, 2.2, 2.3}`。
没有证据时默认展开并留一条 note。`--paren-policy fold/split` 可强制统一。

### 2.6 匹配：确定性优先级 + LLM 兜底

`match/candidates.py`（814 行）先做确定性匹配，只在确定性通道给不出结论时才调模型。
优先级链是：

1. **指标名指纹**（`normalize.py` 归一 + 别名表 + 单位指纹）精确命中；
2. **数值 + 单位**联合命中（`3840*2160` 这类分辨率要按 Decimal 宽度比，不能按字符串）；
3. **区间包含**（`≥600μs` 落在 `200~1200μs` 内）；
4. 多源冲突时按 `DOC_PRIORITY` 仲裁：**检测报告(0) > 技术规格书/服务方案(1) > 产品综合样本(2)**，
   并打 `conflict_resolved` 旗标；
5. 以上都拿不到，且证据里有 `● 指标名：详见检测报告` 这类**指针行**，走指针通道；
6. 再不行才落到 `semantic.py` 的 L2 LLM 兜底；
7. 全部失败 -> `未响应`，投标响应/材料/位置**三列留空**。

离线跑 5 个包时 LLM 通道实际只被调用 2 次（1 次 OCR + 1 次语义），
因为 `ocr_report` 在拿到空响应时会短路、跳过视觉模型重试。

### 2.7 偏离判定链

`judge/decide.py`（711 行）的判定顺序是固定的，**顺序本身就是契约**，
因为每一步都可能提前定案：

```
单位换算(units.close/convert) -> 方向(越大越好 / 越小越好) -> 比较符(>= <= > < 区间)
   -> 区间包含 -> τ 裕度(ratio > 1.10) -> 封闭词表(NEGATIVE_PHRASES)
```

几条必须说清的语义：

- **τ = 1.10，严格大于**。`ratio > tau` 才判正偏离，**取等判无偏离**。
  这个值是从 31 个带比值的样本反推出来的：最大的「无偏离」比值 1.0786，
  最小的「正偏离」比值 1.1333，τ 取在断层中间。`1.05 ~ 1.15` 是低置信带，
  落在里面就打 `low_margin` 旗标并进复核清单。
- **正偏离只由数值产生**。文字型要求（`支持中文界面`）不可能判正偏离。
- **负偏离走封闭词表 + 整短语匹配**：`暂不支持` / `选配（需另行采购）` /
  `标准配置不含，可按需定制` / `部分支持（完整功能需升级版本）`。
  绝不能退化成子串匹配——`支持` 这个子串同时出现在 31 条无偏离与 7 条负偏离里，
  `不支持` 与 `支持` 会互相误伤。
- **未响应 = 恰好三列留空**（投标响应、证明材料文件、位置），偏离类型写 `未响应`。
- 置信度有上限表 `_CONF_CAPS`：`low_confidence` 0.55 / `low_margin` 0.60 /
  `ambiguous_evidence` 0.62 / `ocr_failed` 0.70 / `unit_assumed` 0.75。
  另有 `UNKNOWN_LAYOUT_CAP = 0.40`：版面族没识别出来时，所有行置信度封顶 0.40，
  低于复核阈值 0.85，因此**必然**进人工复核清单，并附一句「请人工核对原文与列的对应关系」。

### 2.8 写出与复核报告

`output/writer.py` 严格按模板的 10 列写出，工作表名 `响应偏离表`，
列宽 `(6, 18, 14, 8, 6, 60, 40, 10, 30, 22)`，表头 `E8EEF4` 填充 + 加粗，首行冻结。
写出前 `dedupe()` 会按 `(标的, 分节, 序号)` 自检去重并告警（对应 `agent.md` 的 N14）。
标准答案里有第 11 列 `判定说明`，**绝不能出现在产物里**——那是打分侧的东西。

复核信息（低置信度行、★/▲ 风险行、主动裁剪清单、告警、阶段计数）**全部走 `--report`
的旁挂 Markdown**，一个字都不进 xlsx。`agent.md` §10.3 解释了为什么这么保守：
`grade.py` 用 `.active` 取表，多一个工作表就有被读错的风险，
几列批注的收益不值得冒这个险。

## 3. AI 工具使用记录

用的是 Codex（GPT-5 系）做长会话结对施工，跨 44 个 session。分工是：
**模型负责穷举与交叉验证，人负责取舍与定值**。下面 5 条是最关键的提示词，
每条后面写清它产出了什么、以及哪里必须由人拍板。

### 3.1 反推 `grade.py` 的评分口径

> 「`grade.py` 是只读的（O5 禁止改）。请逐行读它，告诉我：对齐键是哪几列、
> 哪几列参与打分、哪几列根本不参与、每个指标的分母分别是什么、
> 字符串比较前做了什么归一化。不要猜，给我行号。」

产出：对齐键是 `(标的, 分节, 序号)` 三元组；`招标要求（原文）` 与 `投标响应`
**两列根本不参与打分**；覆盖率分母是 gold 行数，材料/位置的分母是
`judged = n - #(gold 未响应)`（205 - 18 = 187），偏离准确率分母是 `n`——
**三个指标用了三个不同的分母**；比较前调 `grade.norm(s)`，
它做 `re.sub(r"\s+", "", s)` 加一个全角点替换。

这条直接决定了 §5.1 的排期：键错一个字符，该行**所有**指标同时归零。

### 3.2 从 gold 反推 τ 断层

> 「把 5 个包里所有能算出 `响应值 / 要求阈值` 比值的行都列出来，
> 按比值升序排，标出 gold 的偏离类型。τ 应该取在哪？」

产出：31 个样本，最大的「无偏离」比值 `1.0786`，最小的「正偏离」比值 `1.1333`，
中间是干净的断层。

**人拍板的部分**：τ 取 `1.10` 而不是断层的几何中点，理由是 1.10 是一个
「招标方通常会写进文件的整数裕度」，将来遇到未见包时更可能被复用；
同时把 `1.05 ~ 1.15` 定成低置信带而不是让 τ 单点定案——断层只有 31 个样本支撑，
落在带内的行一律进人工复核，这是把不确定性**显式交给使用者**而不是藏起来。

### 3.3 跨页单元格拼接与 `find_tables()` 截断

> 「P1 p8 用 `page.find_tables()` 只出 3 行，实际 15 行。请 dump 这一页的
> 横竖线坐标、词框坐标，告诉我表格检测为什么失败，然后给一个不依赖
> 『表是否闭合』的切格方案。」

产出：失败原因是参数单元格跨页、框线在页边界不闭合；方案是只用横竖线坐标切
列边界与行带，再用词框落点拼文本（就是 §2.2 的 `cellstitch.py`）。
同时模型指出了「续页带前两列天然为空」这个形态，成了 §2.3 第 3 步的判据。

**人拍板的部分**：`MIN_COLS = 4` 这个阈值。模型给的是「按众数取列数」，
但 P4 p25 上 `dominant_hspan`（众数）与 `table_xspan`（交集）会给出不同答案
（框线横跨整页时），所以最终用固定阈值 + 返回空带来表达「这页不是参数表」，
让调用方决定停扫，而不是让统计量替它决定。

### 3.4 按 S4 规则集写 `分节` 策略

> 「这是 5 个包 gold 的全部 `分节` 取值（P1/P2/P4 全空，P3 有 17 个非空，
> P5 有 4 个）。请反推出一套能同时解释这 5 个包的规则集，
> 明确写出哪条规则是为哪个包存在的。」

产出：S4 规则集，以及一个关键发现——**gold 的 `分节` 存的是不含空格的裸 `/`**
（如 `五、医用显示器/2、4K医用显示器`），而我们的输出是 `" / "`（带空格）。
两者只有过 `grade.norm` 之后才相等。

**人拍板的部分**：S4 第 3(b) 条「混合层」判据。模型给的是「同一标的内既有中文序数
又有整数编号时，取中文序数做一级」，但 P5 标的5 的真实形态是
`1、治疗源` / `2、照射光斑面积` / `3、过滤器` **加上**序号 4、5 两条空分节行——
也就是同一个标的内部**部分填、部分不填**（`agent.md` 的 EC-I7 等价类）。
这不是矛盾，是源文件本身的形态，所以判据改成「按行所属的编号块决定，
不做标的级统一」，并保留了填充率诊断。

### 3.5 生成混淆 case 测试

> 「不要给我『每个函数一条 happy path』。按等价类划分：每个能力只留一个代表，
> 然后专门生成**混淆 case**——两个长得像但答案必须不同的输入。
> 例如 `不支持` vs `暂不支持`、`1.7★` vs `▲2.`、`3840*2160` vs `（≥3840*2160）`、
> `4.22次/年` vs `≥4 次`。每条用例必须写明它盯的是哪一个边界，
> 以及它**故意不重复**哪条已有用例。」

产出：`tests/` 的五层结构（unit 377 / integration 22 / golden 13 / invariants 26 / eval 6），
438 个离线用例。

**人拍板的部分**：把「不许重复」从一句要求变成**机器可判的门禁**。
`tests/invariants/test_coverage_matrix.py` 用 AST 扫全部测试文件，
统计每条用例声明的 `@pytest.mark.ec(...)`（等价类，72 个）与
`@pytest.mark.case(...)`（编号用例，104 个），断言三件事：
每个等价类至少被一条用例覆盖、每个编号用例要么被覆盖要么在带理由的白名单里、
**同一个用例编号被声明的次数 ≤ 2**。第三条就是「不应是重复的用例叠加」的可执行形式。
实测分布是 `{1 次: 84, 2 次: 19}`，没有任何编号超过 2 次；
唯一被声明 2 次的 `B22`（中文与空格路径）是故意的——unit 层测进程内克隆，
eval 层测真子进程换 cwd，两者盯的不是同一个边界。
这个门禁写完当场就抓到两个真实的卫生问题：`test_parse_req.py` 与 `test_parse_val.py`
（共 26 个用例）漏了模块级 `pytestmark`，对 `-m unit` 不可见。

### 3.6 哪些是纯人工判断

除了上面各条里标注的，还有几个决定是模型没有参与、或者模型给了相反建议的：

- **「先做覆盖率再做准确率」的排期**（`agent.md` §5.1）。依据是 §3.1 反推出的
  分母结构：键错一个字符全行归零，而原文与响应两列不打分。
  所以 H0–H3 的唯一目标是把 205 个键全抽对，哪怕每行都先输出 `未响应`。
  模型的建议是先做匹配（「那是最有技术含量的部分」），被否掉了。
- **`表行N` 语义的验证方法**。gold 的 `位置` 列有 `检测报告 第1页 表行3` 这种形态，
  离线拿不到 OCR 就没法直接验证。人工找到的判据是：产品综合样本里
  `● 指标名：详见检测报告` 指针的出现顺序 == 报告表格 `序号` 列的顺序，
  且所有报告都是 1 页，所以 `表行N` 里的 N 就是**该页内指针的序号**，
  并且这个序号**按样本页重启**。这条不需要 OCR 就能推出，也让 22/28 条指针行
  的推定判定落在正确的一侧。
- **泄题判定边界**（`agent.md` O10 的具体化）。模型最初把「任何出现在 gold 里的字符串」
  都算泄题，那会让所有用真实数据形状写的测试都变红。人工定的边界是：
  **`招标要求（原文）`、`分节`、`设备名称` 是输入不是答案**（谁都能从招标 PDF 读到），
  只有 `投标响应` 与 `证明材料文件` 两列算答案。再加一条「回声扣减」：
  gold 的 183 条长响应里有 42 条是**逐字照抄招标原文**的，不含任何新增信息，
  必须从泄题语料里剔掉，否则合法描述招标版面的 docstring 会被误判。
- **坏 PDF fixture 在测试运行时生成，不提交二进制**。`tests/fixtures/corrupt/` 是空的。
  截断/加密/0 页/改名图片这 7 种坏文件由 `tests/integration/test_errors.py`
  在 `tmp_path` 里现场造。理由是二进制文件不可 review、不可 diff，
  而且 `fitz` 造不出 0 页文档（`doc.save()` 会抛 `cannot save with zero pages`），
  只能手写 PDF 原始字节——那段字节写在测试里比写在仓库里更清楚。
- **pytest 用 `--import-mode=importlib` 而不是改名**。两个 `test_errors.py` 同名冲突，
  改名更省事，但 `agent.md` §6.2 明确列了 `integration/test_errors.py` 这个路径，
  而且它的 docstring 按名字交叉引用了 unit 层的孪生文件。选 importlib 模式。
- **覆盖率工具自己写，而不是把门禁写成「跑不了」**。`coverage` 装不上，
  §6.9 的 ≥70% 门禁眼看要变成一句空话。用标准库 `sys.monitoring` 写了 232 行替身，
  实测 96.2%。
- **强制 `PYTHONIOENCODING=cp936` 而不是依赖平台默认**。窄码本那条用例如果在
  Linux CI 上跑，平台默认是 UTF-8，用例会**假绿**（子进程根本没进窄码本分支）。
  所以显式注入码本，并且先探测子进程自己报告的编码、断言它确实等于窄码本，
  再比对字节。另外发现 CPython 会把 `cp936` 归一化成 `gbk` 报出来，
  所以比较编码名一律走 `codecs.lookup(a).name == codecs.lookup(b).name`，不用 `==`。

## 5. 已知问题与没来得及做的事

### 5.1 关键项风险识别停在 4/5：这是离线环境的物理天花板

缺的那一条是 **P5 标的5 / 分节「1、治疗源」/ 序号 1.2 / `★输出功率：≥750w`**。
它的实测值只存在于 `02_厂商资料/QM_QM-1220X_检测报告.jpg` 这张图片里，
既不在任何 docx 也不在任何 PDF 的文本层中。取到它只有两条路，两条都断着：

1. **装本地 OCR 引擎**——`agent.md` O3 明确禁止（`cv2` / `rapidocr_onnxruntime` /
   `paddleocr` 都不在环境里，装通的成本远超收益）。
2. **调视觉模型**——账号欠费，见 §5.2。

9 张 `*_检测报告.jpg` 全部检查过：纯 baseline JPEG，没有 XMP、没有 EXIF、
文件尾没有附加的 zip 或文本块。**没有任何离线手段能读出里面的数字。**

于是这条走 `--ocr-fallback assume` 的推定路径：仍然给出材料文件名与
`检测报告 第1页 表行3` 这个位置，偏离类型按「已出具第三方检测报告」推定为**无偏离**，
置信度封顶 0.70，打 `ocr_failed` + `pointer_assumed` 两个旗标，
进复核报告第 3 节。gold 说它是负偏离，所以关键项风险识别少 1 分。

这个缺口是**诚实的**，而且专门立了防作弊哨兵：
`tests/invariants/test_no_leakage.py` 会把那个实测值当哨兵字面量，
扫描仓库里每一个 `.py`——只要有人为了让这一条变绿而把数字写死，门禁立刻红。

同源的影响还有 4 条：`P1 标的1 序号6▲`、`P2 标的2 序号2.3`、`P5 标的1 序号9`、
`P5 标的5 序号1.2★`，都是指针行推定造成的 `负偏离->无偏离`。
28 条指针行里推定方向正确的是 22 条（78.6%）。

### 5.2 API Key 实测状态与由此导致的降级

`agent.md` §9.2 的实测结论，本次施工期间**二次复现**，状态没有变化：

| Base URL | 结果 |
|---|---|
| `https://parvis.zjugpt.com/one-api/v1`（`模型API说明.md` 指定） | **401 `无效的令牌`**，全部模型、连 `/models` 列表也是 |
| `https://dashscope.aliyuncs.com/compatible-mode/v1` | 会话早期短暂可用（0.2~1.4s），约 10 分钟后转为 **400 `Arrearage / overdue-payment`** |

按要求**没有改动任何 Key 配置**，只把「从哪儿读」做成 Provider 无关的两级兜底。

一个反直觉的细节：环境里 `DASHSCOPE_API_KEY` **是存在的**，所以
`Config.offline` 实际是 `False`、`client.enabled` 是 `True`——程序会真的去发请求，
然后每次都失败，`complete()` 返回 `None`，三个 LLM 钩子（L1 OCR / L2 语义 / L3 裁决）
全部静默降级。**净效果与离线完全一致**，代价是每个包多几轮超时等待。
这就是 `selfcheck` 默认离线、`--online` 要显式打开的原因。

连带影响：`tests/fixtures/llm/recorded.jsonl` **录不出来**。
`agent.md` §9.4 第 3 条设想的是「Key 可用时录一次，之后全程回放」，
录制这一步在当前账号状态下无法执行。`tests/fixtures/llm/` 因此是空目录，
`--transport replay` 的代码路径由单元测试用合成语料覆盖，不是真实录制。

### 5.3 `分节` 约定跨包不自洽，S4 是拟合出来的

这是最脆弱的一环，因为它直接决定对齐键。三个层面的不自洽：

1. **跨包不自洽**：P1/P2/P4 的 gold `分节` 全为空；P3 有 17 个非空值（0 个空）；
   P5 有 4 个值，其中 9 行非空且全部集中在标的5。同一个「什么时候该填分节」的问题，
   5 个包给了 3 种答案。
2. **与我们的输出形态不同**：gold 存的是**不含空格的裸 `/`**
   （`五、医用显示器/2、4K医用显示器`），我们输出的是 `" / "`（`section.py` 的 `SEP`），
   并且保留原文里的空格。两者**只有过 `grade.norm` 之后才相等**。
   任何拿 `(标的, 分节, 序号)` 直接跟 gold 比键的代码都必须先 norm 分节，
   否则 P3 会整包对不上（这个坑在 `tests/golden/test_gold_all_keys.py` 里踩过并修掉了）。
3. **同一标的内部部分填部分不填**：P5 标的5 的序号 1.1~3.2 有分节，
   序号 4、5 是空的。这不是 bug，是源文件形态。

S4 是为了同时解释这 5 个包而拟合的规则集，**未见包很可能失效**。
所以做了三件事兜底：`--section-policy s2/s1/off` 可切换；
填充率诊断（>80% 时告警，但文案里写明 P3 那种 100% 是正常的）；
`(标的,分节,序号)` 重复时写出前自检去重并告警。

### 5.4 匹配层剩余的偏差

偏离准确率 0.927，15 条 off-diagonal。逐条查过根因，分成三类：

**(a) OCR 天花板**（§5.1）：4 条，物理上无解。

**(b) P3 的 6 条 `无偏离->未响应`**：全部集中在 P3，根因是**分节上下文不足以区分
`4K3D显示器` 与 `4K显示器`**。P3 有 71 行却只折叠出 24 个不同的 `(标的,序号)` 对，
同一个序号在 3 个不同分节下重复出现（`1、数量：1 台` 在 gold 里就有 3 条，
分别属于 `四、配套LED 冷光源` / `六、气腹机` / `九、配置适合腹腔镜及开腹手术使用电刀：`）。
匹配时如果不带足分节上下文，就会把证据配错行，或者两条都配不上。
这一族**没有修**：修它需要改分节上下文的构造方式，而 P3 的位置命中率 0.836
已经是全局最低，改动有回归风险，收益只有 P3 一个包。

**(c) 数量/尺寸的成对错位**：P3 里有两处 `gold 说表行37、我们说表行38`
与 `gold 说表行38、我们说表行37` 的互换（`尺寸≥32 英寸` / `尺寸：≥55 英寸`）。
偏离类型判对了，只有位置错。同样是 (b) 的分节上下文问题。

另有一处**与 `agent.md` 自身规则冲突**的：P3 标的1 序号3 `输出分辨率`，
gold 说材料是「产品综合样本 第1页」，我们按 `DOC_PRIORITY` 给了「技术规格书 表行5」。
`agent.md` 的 X4 规则明确写「多源一致时取规格书」，gold 却取了样本。
**保留了 X4 规则**，因为为一个包破一条全局规则的代价更大。

单位词表还有几个已知缺口：`辆` 不在词表里；`μ` 与 `μm` 不互为别名
（导致 `_interval_in` 返回 `None`）；`次/年` 与 `次` 被 `unit_conflict` 判成量纲冲突
（扣 0.15 分，直接挡住了 P3 标的2 序号2.2 那条 `每年提供≥4 次`）；
`ml/h` 的循环小数靠 `units.close()` 的容差吸收掉。
`count_question` 通道救不了单字修饰语：`泵数量` 对 `具有≥4 个泵`
的名字相似度被压在 0.30，总分 0.48，够不上阈值（P5 标的1 序号3 因此漏配）。

### 5.5 P4 的 1 条多余条目

P4 输出 37 行，gold 是 37 行原始 / **36 行计分**，所以多余 1 条。
这是**故意的**：gold 那一行是 `1.9.1`~`1.9.6` 三级编号里的一个引导行，
删掉它会让 P4 的编号序列出现无法解释的空洞，而多余条目的门禁是 `≤2/包` 且**不计分**。
用 1 条不计分的多余换编号序列的完整与可复核，是划算的。
P4 同时是唯一一个偏离准确率 1.000 **且混淆矩阵 off-diagonal 为空**的包。

### 5.6 摄取、缓存与写出的已知瑕疵

这些都不影响 5 个训练包的成绩，但换包就可能咬人。按影响面排序：

- **`pack_hash` 不读文件内容**，只看路径与文件清单。改了 PDF 内容而文件名不变时，
  阶段缓存不会失效。开发时用 `--no-cache` 或 `--from-stage` 绕开。
- **`open_pdf` 不是损坏检测器**。MuPDF 的容错能力**依赖具体内容**：
  一个砍掉一半的 CJK PDF 会被打开成 1 页的**空**文档（不报错），
  只丢了 xref 的 PDF 会被完美修复。所以「PDF 半坏」这种输入可能静默产出空表。
  另外把一个 JPEG 改名成 `.pdf`，MuPDF 会自动包成 1 页 PDF，
  于是错误消息里那句「不是改了扩展名的图片」的提示分支**永远走不到**。
  唯一内容无关的致命截断是 ≤128 字节，测试就按这个值造坏文件。
- **`cell_text` 的两个字形瑕疵**：字形横跨 x 裁剪线时被截断；
  y 裁剪线切在字形腰部时会插入一个空格。归一化能吃掉大部分，但不是全部。
- **`writer._from_template` 会静默改写被篡改的表头**，不发告警；
  它会重命名工作表、删掉模板里的残留行，但**不会**重新应用 `freeze_panes` 与列宽。
- **`review.write_report` 不透传 `generated` 时间戳**，所以报告文件不是字节可复现的
  （秒级粒度）。这曾经让 `B22` 那条「两条路径产物一致」的用例偶发红，
  现在改成只比对去掉标题行与时间戳行的内容。
- **xlsx 本身不是字节可复现的**：同一个包跑两次，产物 8320 vs 8321 字节。
  所以所有产物比对都是**单元格级**的，没有一处比字节。
- **`review.render` 的复核清单按字符串排 `序号`**，于是 `10` 排在 `3` 前面。
  对人工复核不致命（清单同时按置信度升序），但确实不是数值序。
- **`deviation_counts` 会给意料之外的偏离串凭空造一个键**，
  而 `render` 的分布行与 `summary_line` 都会**静默丢掉**这种键。
  当前 `DEVIATIONS` 是封闭四元组，触发不了，但契约上是脆的。
- **`fold.resolve` 的服务标的守卫是空集陷阱**：`scopes` 为 `None`/`[]`/全是设备标的时，
  守卫条件成立，于是**每个**标的的 `（N）` 子项都会被折叠。
  `scope.apply` 的 `is_service` 守卫同样在训练集上不可达，
  且空的 `scopes` 列表会静默裁掉服务标的的尾巴。
- **`build_lotmap` 遇到型号-标的冲突只告警不报错**。`agent.md` 的 B11 要求报错，
  但那与 §3.8 的容错原则矛盾（宁可给一个带告警的结果，也不要拒绝产出）。
  **B11 是唯一一条没有实现的编号用例**，理由写在
  `tests/invariants/test_coverage_matrix.py` 的 `UNIMPLEMENTABLE` 白名单里，
  由门禁双向断言（白名单里不许有已实现的项，也不许有漏项）。
- **`vendor_docx.to_evidence` 的 `no.isdigit()` 兜底**会让空序号与真实序号相撞，
  并且放过全角的 `３`。
- **`lotmap.doc_type_of("服务方案技术规格书.docx") == "服务方案"`**，
  与 `vendor_docx.TITLE_SPECS` 的顺序敏感规则**互相矛盾**。
  两个模块对同一个文件名给出不同的文档类型。
- **`vendor_catalog` 的指针序号按样本页重启**（§3.4 人工验证的那条），
  但 `attach_lots` 在 `表行N` 越界时仍然会回填 `filename`。
- **`body_of("4K 采集摄像头") == "K 采集摄像头"`**：吃掉了裸的前导数字。
  `fold.title_of` 继承了这个 bug。`section_context` 不剥 `（N）`，
  且 `section_context("2.1 数量") == "1 数量"`。
- **`_MODEL_LINE` 要求字面的冒号**，`TITLE_SPECS` 顺序敏感，
  `vendor_docx` 的表头检查是**交集**而非相等，
  所以一张只有表头的表会同时给出 `rows == []` 与 `warnings == []`。
- **`parse_report_json` 收到没有 `rows` 键的 JSON 时给 0 行且无告警**；
  收到完全不是 JSON 的字符串时报的是 `substring not found`（底层异常串）。
- **`chinese_to_int('一二') == 12`**：中文数字解析是逐字累加的，不校验合法性。
- **`load_config` 在没有 Key 时强制 `offline=True`**，
  这意味着 `--offline` 与「忘了配 Key」在产物上不可区分。`--verbose` 会打出
  `Key 来源=无`，这是唯一的区分手段。
- **`stage_index` 显式拒绝 `bool`**（在 `int` 分支之前），
  因为 `isinstance(True, int)` 为真，`--from-stage True` 否则会被当成阶段 1。

### 5.7 只支持 A/B/C 三种版面族

未识别的版面走降级路径 `tender._extract_unknown`：全文捞参数行，
全部挂到标的1，分节留空，置信度封顶 `UNKNOWN_LAYOUT_CAP = 0.40`，
并打一条大写告警。**不抛异常**（`agent.md` N13 的要求）。

降级路径自己也有一个已知缺陷：`extract_flat_requirements` **完全忽略 `param_pages`**，
在真实 P3 上会捞出 95 条「要求」，其中大部分的文本就是裸页码 `1`~`93`。
这些行的置信度都在 0.40 以下、全部进复核清单，所以不会静默污染结果，
但产物会是垃圾。真遇到未知版面，正确做法是先扩 `detect_layout`，不是硬跑。

### 5.10 测试框架自身的边界

- **`offline_run` 是 session 级记忆化的**，返回的 `PackResult` 按契约**只读**。
  任何测试就地改它都会污染同 session 的其他测试。这条写在
  `tests/conftest.py` 的 docstring 里，但没有机器强制。
- **覆盖率工具量不到子进程**（§1.4）。`tests/eval/` 起的 6 个子进程、
  以及 `run.py` 自身的行，都不在 96.2% 里。
- **网络守卫靠 monkeypatch `socket`**，不是真的断网。`eval` / `network`
  标记的节点会跳过这个守卫。
- **`tests/eval/` 没有 60s 门禁**（实测 44s），因为它要真跑 5 个包的完整流水线。
  离线套件 40.0s 对 60s 门禁只剩 20s 余量，加用例时要注意。
